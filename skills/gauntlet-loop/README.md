# gauntlet-loop — design notes and decisions

`SKILL.md` is what Claude loads; `references/` is what the lead reads when it runs. This file is for humans: the decision behind every place the skill could have gone another way. Each one names the alternative, why this one, what it costs, and the evidence — so a later change is a change of mind, not a drift.

Evidence cited by title is the LLM-as-judge literature these choices lean on: Zheng et al. 2023, *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena* (position bias, verbosity bias, self-enhancement bias; pairwise beats absolute grading); Wang et al. 2023, *Large Language Models are not Fair Evaluators* (swapping candidate order flips verdicts; evaluate both orders); Panickssery et al. 2024, *LLM Evaluators Recognize and Favor Their Own Generations*; Verga et al. 2024, *Replacing Judges with Juries* (judges from different model families are less biased than one judge); Huang et al. 2023, *Large Language Models Cannot Self-Correct Reasoning Yet*. Harness facts live in `references/harness-claude-code.md`, each with the date and version it was observed on; the design documents this release was built from are in `dev/gauntlet-loop/design/` at the repository root (`intent.md`, `spec.md` with its amendments, `plan.md`, `acceptance.md`).

## What is in this folder, and why

Everything here is something a session or a run uses. Nothing else ships: the tests, the eval suite and the design documents live in `dev/gauntlet-loop/` at the repository root, so the copy that lands in `~/.claude/skills/` stays small.

The skill works at two levels, and you only need the second for long unattended runs.

**Instructions.** Enough to write a prompt, and to run a loop you are watching.

| Part | What it is | Who reads it |
| --- | --- | --- |
| `SKILL.md` | Write mode: goal in, one paste-ready prompt out. The only file loaded by default | Claude, in any session that triggers the skill |
| `references/` | Run mode: how the lead runs the loop, one file per kind of work, the controller on one page, the harness facts, one worked run | The lead, and only the files a run needs |
| `README.md` | This file: every decision, the rule ledger, the mechanism table | You |

**Enforcement.** A skill can only ask a model to follow a rule. Over a two-hour run with dozens of agents, asking is not enough: a lead misremembers which win was confirmed, a stuck builder edits the test instead of the code, a curious critic opens the workbench and learns which side is ours. None of that is defiance; it is drift and the shortest path, and one instance can end a run on a false win. These parts put something that is not a model behind the rules that must always hold. They do nothing until `install/claude_code.py <repo>` copies them into a target repository and the result is checked in; without that, a run says it is Tier 3, "blind by instruction", and carries on.

| Part | What it enforces |
| --- | --- |
| `agents/` | Five role definitions with tool allowlists: a critic gets read and shell and nothing else; no role can message or spawn; the two critic definitions pin two different models, which is what makes "confirmed on a different model" checkable |
| `hooks/` | Denials the harness applies before a tool runs: a critic cannot read outside its pair, a builder cannot leave its worktree or touch tests, secrets, migrations or deploys, nobody edits the floors or the run's state, and only the harness's own stop hook can report what an agent concluded |
| `bin/gauntletctl` | The run's bookkeeping, in code instead of in the lead's memory: an append-only event log, a fixed table of legal moves, label assignment from a hidden seed, the budget, and the status line the loop's evaluator reads. The lead records judgments; it cannot record a win |
| `policy/v1.json` | The numbers and pattern lists the two above read, pinned per run. It names which two models confirm, never whether |
| `permissions/allowlist.json` | The minimal allow and deny rules a run needs, so a permission prompt does not stall a fan-out and private state is unreadable by any tool |
| `install/claude_code.py` | Copies the five parts above into a repository, merges its settings, and writes the manifest that `gauntletctl detect` verifies before it will call a run Tier 2 |

The rule ledger below says, rule by rule, which of these stands behind it, and which rules are still only instructions.

## Decisions

**D1 — One short prompt, not a method document.** Alternative: a method the agent follows plus a long orchestrator prompt with numbered steps. The method's own first rule is "give it the goal, not your implementation"; a prompt that prescribes decomposition and procedure replaces the agent's judgment with the author's. The paste prompt states the whole loop in about 230 words and leaves every other decision to the lead. Cost: a session without the skill installed has less to go on — accepted, because the prompt is complete in itself and the skill exists for the rest.

**D2 — The exit is a confirmed win or the user; never "no improvement in N rounds", never a round count.** Alternative: stop when two rounds bring nothing, or after a budget of rounds. A plateau is the signal to split the piece or change builders — the escalation ladder (D9) exists for exactly that — and a "no improvement" exit is the lead grading its own progress. Cost: as first written, an unattended run against a bar it cannot reach spent until the user stopped it; D21 closes that with a ceiling that counts and never grades, so this entry's principle stands and its cost no longer does.

**D3 — Prefer the hardest bar the agent can genuinely reach; an out-of-reach bar only when the user wants the pull.** Alternative: always aim past reach. An unreachable bar pulls the work further and is stopped by hand; a reachable one gives a defined exit and a result at least as good as a real thing. Both are legitimate. The skill offers both and says which is which, because under `/goal` the choice decides who ends the run. Every run now carries the second exit in its first line (D21), so even that run has an end the evaluator can judge.

**D4 — Pairwise pick for taste; command floors for everything objective; no absolute scores.** Alternative: PASS/FAIL or a score per criterion, with "default to FAIL" as the correction for leniency. Pairwise judgments are more consistent than scores (Zheng et al.), and scores drift upward across rounds as the judge anchors on its last one. What is objective — tests, contrast, false positives, a citation opening — is not an opinion, so it is run by command before any critic. The split is principled: absolute where a command decides, pairwise where taste decides. The pairwise equivalent of "default to FAIL" is "a tie is a loss for ours", which the prompt carries.

**D5 — Observations before the pick; one gap, stated as an observation, never as a fix.** Alternative: a list of every defect with prescribed fixes. A judge that picks first writes observations to fit; reasoning-first improves agreement (Zheng et al.). One gap, because ten gaps get ten shallow patches and no re-think. No fixes, because a fix is one critic's prescription — the next critic would prescribe differently — and a builder handed fixes optimises for critic taste instead of the bar; it is "give the goal, not the implementation" applied to the critic. Cost: a piece with several orthogonal defects surfaces them one round at a time; splitting a quality dimension into its own piece (D6) is the remedy when that is too slow.

**D6 — One critic per verdict, not a panel of lenses.** Alternative: several critics per round, one lens each (correctness, performance, aesthetics, accessibility), votes combined. The honest case for a panel is that identical judges share blind spots (Verga et al.). The skill gets that diversity without a panel because each lens already has a better home: objective lenses are command floors; reading lenses are the FLOOR lines every critic checks on both sides; a taste dimension that deserves its own judgment becomes its own piece with its own loop; and model diversity — the kind the evidence actually shows helps — comes from the confirming critic running on a different model. What a panel would add is a vote on the pick, at N critics per round, for a gain that only matters in the losing case, where a wrong verdict costs one round. The second judgment is spent where a wrong verdict is expensive instead (D7). Where a panel would still win: a single piece whose taste dimensions cannot be split — rare, and the assembled-whole gate catches what per-piece verdicts miss.

**D7 — Confirm wins only, with the order swapped and a different model; no minimum rounds.** Alternative: a minimum round count before a pass counts, on the theory that the first pass is often a lenient critic. The two errors are asymmetric: a false win ends the loop early, a false loss costs one more round. So the second critic is spent on wins. The swap is the balanced-position check Wang et al. propose; a new coin flip repeats the first order half the time. The different model breaks self-preference (Panickssery et al.): against a human-made reference, a same-model critic is a thumb on ours. A minimum-round rule names the same problem but wastes rounds when the work is good and does not fix a lenient critic — it passes again.

**D8 — Blind by procedure.** Alternative: tell the critic the reference by name and pass the builder's notes along. The lead fetches and freezes; the critic never hears the reference's name (a critic told "Nike" finds the swoosh), never sees builder notes (it anchors on the justification and agrees — the self-review failure in Huang et al.), never sees history or which side changed (a reused critic knows which side is ours), and no subagent is named after a piece, round or role. D16 moved all of this from the prompt onto the filesystem: role definitions that list no messaging tool (so no roster is shown at all), a hook that denies a reader everything outside its pair, and a claim stated at the tier that is active. Builders return one line — the path — so nothing leaks forward and the lead's context stays small over a long run. Residual risk: a famous reference can be recognised from its pixels or its voice; the answer is to compare pieces rather than whole pages, and to prefer the less iconic of two equally hard references.

**D9 — The builder keeps its context while the gap changes; a repeated gap escalates.** Alternative: a clean-context builder every round. Continuity is cheaper than re-briefing, and a builder that remembers its last change closes the next gap faster. The moment it stops working — the same gap twice — is also the signal that the builder's frame is the problem, so the ladder is: split the piece on that gap, retire the builder for a fresh one given only the artifact and the gap, then variants, each with a different one-line approach: two first and a third only if both lose (D27), each judged as an ordinary pair. A spent allocation climbs the same ladder (D21), and a piece the whole ladder could not move parks for a human (D19). A clean context every round throws away the good case to avoid the bad one.

**D10 — Smoothing at the end of each wave and at the gate; the whole is judged.** Alternative: smooth once after convergence, or never judge the whole. Smoothing while pieces are still moving would silently invalidate confirmed wins, so it runs only on a finished wave, touches as little as harmonising needs, and every piece it touched is re-checked by one fresh critic with the order swapped from its last verdict — a piece that has won twice needs one check that it still does, not a third full confirmation; a loss reopens it. At the gate: smooth, re-run the floors, judge the assembled whole against the whole reference, a loss becomes a "coherence" piece. Cost: a smoother plus one critic per touched piece per wave; it buys seams found while they are cheap instead of all at once at the end of a many-hour build. D35 made the wave smoother conditional on a recorded shared edge and the rechecks conditional on a diff no floor can see; the whole is still always judged.

**D11 — `/goal` leads the prompt; `/loop` is the fallback.** Alternative: a `/loop until …` line inside the prompt. That line is plain text — a slash command counts only as the first token — so the lead would have to invoke the loop skill and reschedule every turn; the same model that runs the loop could end it (`stop: true`), the builder grading itself one level up; forgetting twice kills the run silently; every wakeup waits at least a minute, on a task that expires in seven days. `/goal` moves the loop into the harness: the whole prompt is the condition (up to 4,000 characters), a separate small model judges it after every turn from the transcript, the next turn starts at once, evaluation waits while subagents run, it survives forgetting, returns on `--resume`, and only the user clears it. Two adaptations: the lead ends every turn with the count of confirmed pieces (the evaluator cannot run commands) and never writes that the bar is out of reach (the evaluator can clear a goal it judges impossible). The residual risk, shared with `/loop`, was a lead that claims "all confirmed" without the verdict files behind it. D24 closes most of it: the status line and the gate evidence are controller output computed from attested verdicts, the lead cannot submit a win, and the winning turn ends with the pasted output of `gauntletctl gate`, so the evaluator reads evidence rather than a bare claim. `/loop` remains as the first token where `/goal` is unavailable (hooks disabled), and in run mode when the user says "run it" in-session; never mid-prompt.

**D12 — A harder bar is a new run.** Alternative: raise the bar mid-run once the first one is met. Raising it invalidates every confirmed win and, under `/goal`, changes nothing in the condition the evaluator is judging. Finish, then start again with the result as the starting artifact.

**D13 — Examples are verdicts in the required shape, not narrative runs.** Alternative: long worked example runs in prose. A run in prose teaches by imitation, and what gets imitated is its shape — a critic that grades and prescribes, a builder that explains itself — which is exactly what D4–D8 forbid. What ships instead: a verdict in the exact required shape at the end of every domain file, a workbench snapshot in `references/running-the-loop.md`, and one end-to-end run in the skill's own shape, `references/example-run.md`, which since D24 is an event log: every status line and metric in it is the controller's output, replayed by a test (`dev/gauntlet-loop/tests/test_example.py`), so it cannot drift from the code. It shows a red floor, a loss routed as one gap, a discarded verdict, an accepted NOT REPRODUCED, a swapped confirmation on another model, a repeated gap split, a parked piece a human resumes, a champion-challenger piece converging, a compaction turn, the whole gate lost on coherence and won, one failure of each class, and the pull request. A trace in the right shape teaches the right shape by imitation.

**D14 — The lead writes the tests, eval sets and held-out material; no critic co-authors a floor.** Alternative: the critic writes or keeps the tests. A critic that wrote the tests judges with a stake in them, and since critics are fresh every round, "the critic keeps the held-out set" cannot even be carried out. The lead never picks a winner, so holding the floors is not a conflict; a floor the lead wrote wrong is corrected once, logged, and every confirmation it touched is re-run. Since D20 and D33 a disposable `author` may implement the files from the lead's brief: it never builds and never judges, the lead specifies, reviews and keeps custody, and `hooks/protect_floors.py` denies the floor trees to everyone else, the author included once the plan is committed.

**D15 — Where the money goes, and where it does not.** Cost matters once quality, goal and bar are met, so every agent has to buy something. What buys quality runs on the strongest model: the builder and the first critic — a weaker builder costs a round, and a round costs a critic, so the cheap builder is the expensive one. What is a check rather than a judgment runs cheaper: the smoother, and every floor, which is a command. The confirming critic is not on that list: it is the last check against a false win, the one error that ends the run early, so it runs on a different model as strong as the first — a first draft of this decision let it be the faster model, the same mistake as the effort one. What is skipped: a critic for a piece that already failed a floor; a second critic for a loss (a false loss costs one round, a false win ends the run); loops for pieces not worth one - a piece is split as fine as it can still be paired with a matching part of the reference, and what is not worth its own loop is built once inside a piece and judged at the whole gate; and the word `ultracode` in the prompt — typed in a prompt it only turns that turn into a workflow script, the wrong tool for round zero, and changes no effort. Effort itself is not skipped: it is a session setting that reaches every builder and critic, and the default `high` shortchanges the two agents that buy quality. Which setting is D36's business: this entry first said `high`, then `ultracode`, and both were wrong. Alternative: the strongest model everywhere and no skips — more tokens for the same exits.

**D16 — Blindness holds on the filesystem, claimed at the tier that is active.** Alternative: blindness by prompt only, which is what D8 shipped. A critic that is told nothing can still read the workbench, the A/B mapping or an earlier verdict, because they sat in the tree it was pointed at. Now each role is a subagent definition with a tool allowlist (`agents/`); a `PreToolUse` hook (`hooks/critic_blind.py`) denies a reader every path outside its own pair, rewrites its shell to start inside the pair, and logs each block as `BLIND_BLOCK`; readers omit the repository's `CLAUDE.md`; the mapping, manifest, verdicts and workbench live under `.gauntlet/`, outside every pair; and the claim is tiered, so a run with nothing installed says "blind by instruction" and a run with hooks says "enforced policy", never "isolated". The hooks are registered in settings and branch on the agent type, not declared in the definitions' frontmatter: frontmatter hooks are skipped without warning in a folder whose trust dialog was never accepted, and a guarantee that can vanish silently is not one. Cost: five definitions, three hook scripts and an installer to maintain, two model pins that age with the harness, and a few milliseconds per tool call for every agent. Evidence: spikes S2, S5, S6, S9, S10 and S13 in `references/harness-claude-code.md`, and the live check recorded there (a reader denied the workbench, the state file, a rootless glob and the reference, four blocks logged).

**D17 — A referent per piece, or champion-challenger; a manufactured bar is refused.** Alternative: when no single reference covers a bespoke system, build it twice from the same spec and judge one build against the other. A real run did exactly that: both builds inherited the spec's blind spots, both passed a floor that tested neither defect the critic later found, and nothing in the skill said either was wrong. Now round zero gives each piece its own named, fetchable referent; a piece with no matching part anywhere runs champion-challenger beside the nearest real referent, converges only when a challenger has failed twice and two fresh critics on different models each name no movable gap, and is reported as "converged against <referent>", never as "beat the bar"; write mode refuses a manufactured bar and a suite alone by name, and says a goal with no referent for any piece is not a gauntlet. The convergence check is stricter than the first draft of the intent, which let one critic end the piece: no terminal claim in the method rests on one critic. Cost: one extra artifact in every champion-challenger verdict, one more invocation per converging piece, and some goals are turned away. Evidence: the motivating run, kept as the first case in `dev/gauntlet-loop/eval/write-mode/cases.json`.

**D18 — The loop cannot wander: a boundary the builder is told and a hook enforces.** Alternative: trust the builder prompt. A builder closing a gap will edit a held-out test, add a migration or run a deploy if that is the shortest path, and a permission prompt in a fan-out stalls every parallel piece. So "never" phrases from the goal become invariants in the bar sentence, checked by command where a command can; `hooks/builder_boundary.py` binds a builder to the worktree it first writes in and denies everything outside it, plus migrations, infrastructure, deploy configuration, secrets and floors inside it, held-out material for reading, and deploy, publish, push, migrate and package-install commands; `hooks/protect_floors.py` denies the floor trees to every agent, the lead included, except an `author` the lead dispatches; a denial explains itself and says to return `BLOCKED:`, which parks the piece while the others continue. A hook the lead installs constrains the agent that installed it, so it counts as enforced only when it was checked in before the run; otherwise the ledger says advisory. Cost: coarse string matches park a builder now and then for something harmless, a builder cannot add a dependency without a human, and the lead installs locked dependencies per worktree itself. Evidence: `dev/gauntlet-loop/tests/test_hooks.py`; spikes S5 and S10.

**D19 — A stalled piece parks and reaches a human; the run goes on.** Alternative: let the ladder repeat until the user notices, which is what D2 and D9 amounted to for a piece no rung could move. A piece now has exactly one of seven states with a fixed table of moves between them, and when split, fresh builder and variants have all failed on the same gap it parks, with its last verdict and one builder account, listed first in the report. This does not reopen D2. D2 refuses an exit that grades progress: "no improvement, stop" is the lead judging its own run. Parking is per piece, is triggered by a fact (the ladder is exhausted, a builder was blocked, an action is irreversible), says nothing about whether the bar is reachable, never lowers it, never counts as a win, and never ends the run; the run's exits are what they were. `PARKED` leaves only by a human. Held-out floors still run every round before any critic and again on every merge. Cost: a run can finish with pieces a human has to pick up, and the workbench carries a state column. Evidence: the intent's motivating review, which found no path for a stalled piece to reach the user.

**D20 — Floors are honest: DERIVED is marked, findings become floors, and the plan is committed.** Alternative: the lead writes whatever floors it sees fit and says nothing, which is what D14 allowed. In the motivating run both builds passed a floor that tested neither defect the critic later found, and nothing marked that floor as the lead's own invention. Now any test, held-out case, claim list or eval split the user did not supply is marked DERIVED; a defect a critic finds that a command could have caught becomes a held-out test in the same round, written by an `author` the lead dispatches and logged with the old and new floor; a builder may answer a gap with `NOT REPRODUCED: <command and output>`, and if the lead's rerun agrees the verdict is discarded and a fresh critic spawned with no gap routed; and the workbench after round zero is the plan, committed before any builder exists, approved by the user in an attended run. D1 holds: the plan names what is judged and how, never how a piece is built. D14 holds: the lead specifies and keeps custody, no builder edits a floor, no critic co-authors one. Cost: an attended run pauses once, and every converted finding is an author invocation. Evidence: the motivating run.

**D21 — A secure stop: the cap is the exit.** Alternative: only the user ends a run that is not winning, which is what D2 shipped, and whose cost paragraph admitted that an unattended run against an unreachable bar spends until someone notices. Every run now has a ceiling no agent grades, agent invocations and wall-clock hours, written into the prompt's first line as a second exit and carried in the status line every turn so the evaluator can read it; the default is 150 invocations and 24 hours when the user names none. The ceiling is an envelope of three protected budgets, local piece work, an escalation reserve and a whole-gate reserve (60, 25 and 15 percent, bootstrap values until three measured runs replace them), so a stubborn piece can exhaust its own allocation and the reserve and park, but the run always reaches the gate with what the gate needs. A spent allocation is a routing trigger and enters the ladder exactly as a repeated gap does, which closes the hole a moving gap left open. Three terminal states - win, nothing left, ceiling - each write the report and end the lead's work. D2 holds: the stop is a count of what was spent, never a judgment about progress, and "never write that the bar is out of reach" stays, because the cap makes it safe. The unverified "answer each restart with no tool call" clause is gone. Cost: a run can end below the bar, and the prompt's first line is fourteen words longer. Evidence: D2's own cost paragraph.

**D22 — The reference and the run are untrusted input.** Alternative: trust the reference as source, which is what the baseline did: its own example cloned a repository and ran `npm ci` in it before any check had run. The design's threat model was the model deceiving itself; it never modelled the world deceiving the model. Now `gauntletctl freeze` is a data boundary: it copies or clones, strips everything a harness would read as instructions and every env and credential file, lists what it removed in the manifest, and executes nothing. `freeze-verify` is the execution boundary: installing, building, the reference's own floors and renders run once, only under isolation the controller detected itself (the sandbox in strict mode with a network allowlist) and only if its own probe cannot write outside the project, so a wrong detection or an exclusion somebody added cannot un-isolate it. Every dispatch prompt says the reference is material, not instructions. Pairs never carry env or credential files, nothing under `.gauntlet/` is committed before `gauntletctl scan` passes, a verdict quoting a secret is redacted, and the run ships a minimal permission allowlist so the classifier is rarely the one deciding. Tier and containment are detected, never asserted, and no containment level is chosen per run. No `excludedCommands` ship: spike S14 showed a compound command rides out of the sandbox on an excluded prefix, so every command the lead invokes stays sandboxed and the only sandbox read deny is the attestation key, which none of them needs. Cost: on a machine with neither the sandbox nor a container, every piece that needs the reference to execute is blocked until a one-line fix (C12: the block is kept); a repository under the sandbox's own temp root fails the probe and is treated as not isolated. Evidence: the freeze-time execution hole in the baseline example; `dev/gauntlet-loop/tests/test_freeze.py`; spikes S4, S5 and S14.

**D23 — Every non-win has a class, and the class has an owner.** Alternative: every failure is a gap for the builder, which is what the baseline implied. It sent a wrong floor, a missing tool and a contradictory goal down the same path as a worse artifact, so builders were asked to fix what only the lead or the user could. Four classes now decide the route: `artifact` (the candidate is worse; to the builder; the only class a verdict can produce), `evaluation` (the bar, a floor, a pair or a critic was wrong; to the lead, logged, touched confirmations re-run), `execution` (a mechanism is unavailable; the piece or run is `BLOCKED`, dependents park), and `scope` (the goal is inconsistent; written as an intent draft, never as a piece, so a whole-gate loss that traces to the spec does not become an endless coherence piece). `BLOCKED` is a lead state and never a verdict: critics still answer A or B. Cost: one more word per gap-log entry, and the lead owes a classification for every non-win. Evidence: the metrics count by class, so a run whose failures are mostly `evaluation` says the floors were wrong, not the builders.

**D24 — Bookkeeping lives in code: a deterministic control plane.** Alternative: the lead keeps the run's state in prose, which is what every earlier version did: which piece is in which state, what the last verdict was, whether a win awaits confirmation, how much is spent, what comes next. Models are unreliable at long-lived mutable state, prose cannot reject a transition, and every line of bookkeeping in the lead's context is the most expensive line in the run. `bin/gauntletctl` is one stdlib Python file. The append-only event log is the truth and state is its fold through one pure function, so replaying the log reproduces the state exactly; a fixed table of moves rejects everything else (`ACTIVE` to `PROMOTED`, `CONFIRMED` without a confirmation, any exit from `PARKED` but a human's); the lead records twelve judgment events and cannot submit a fact, because facts come only from the command or hook that observed them; verdicts are attested by the harness's own stop hook for a registered, single-use agent of the expected type, translated through a mapping the lead never sees, and a forged attestation collides with the genuine stop and is voided with everything that rested on it; pairs come from a seeded, idempotent command, so a retry cannot change the experiment and a label cannot leak by habit; the envelope is escrow with no debit path from a piece to the gate reserve; leases keep a dead agent from leaving a piece active forever; the policy is pinned per run and has no parameter for critic count, critic strength, confirmation, blindness or what a win is; and the status line, the workbench, the gate evidence and the metrics are computed, never composed. There is one lead model and no meta-agent: the controller never makes a judgment call and the lead never makes a bookkeeping one. `hooks/controller_only.py` keeps every agent's tools off the state, the log, the pairs and the tooling itself. Cost: a Python 3.11 runtime, about a thousand lines and a hundred tests to maintain, and a run cannot start without the install. At Tier 2 attestation proves provenance structure, not origin: a forgery is caught only when the genuine stop fires, and spike S3 showed a reader that hits its turn cap never stops, so its attempt is closed by its lease instead. Evidence: the intent's argument about mutable state in context; `dev/gauntlet-loop/tests/`; spikes S2, S3, S4, S11 and S12.

### Cost: where consumption falls without touching the machinery

On this README's own estimate rounds dominate, every critic re-inspects both sides from scratch, every piece carries two confirmations and fixed per-agent overhead, and the lead repeats the same preparation in prose every round. D25 to D36 take the savings from there, never from fewer critics, weaker critics or skipped confirmations. Each names what it costs in quality.

**D25 — Split coarse first, split reactively.** Alternative: the smallest pieces that can be judged alone, which is what the prompt asked for. Every piece pays two confirmations and per-agent overhead whether or not it needed its own loop. The prompt and round zero now ask for the coarsest pieces that can still be paired with a matching part of the reference and run without sharing an edge; the ladder already splits where a repeated gap proves it is needed; schema, migration, policy and config files count as shared by rule. Quality cost: a coarse piece with several orthogonal defects surfaces them one round at a time until a repeat splits it.

**D26 — The builder runs the visible floor before returning.** Alternative: the lead runs every floor. A round that comes back red on tests the builder could already see is a lead turn and a message for nothing. The builder runs the required suite and returns only when it is green, with the summary line; the lead still runs what the builder must not see (held-out, hostile, benchmark), and the critic remains the fresh-context check. Quality cost: none on the checks that gate; a builder could misreport its summary line, which the lead's floors catch a step later.

**D27 — Staged variants.** Alternative: three variants at once, as D9 had it. Two divergent approaches first, a third only if both lose; the controller rejects a selection that names more. Each variant is judged as an ordinary pair and a variant's win is confirmed like any win. Quality cost: when the third approach was the right one, it arrives a round later.

**D28 — No idle turn boundaries.** Alternative: hold a builder's return for the next turn. Each boundary costs an evaluator pass and a re-orientation, so a return is acted on in the turn it arrives: floors, pair, critic. The rule is against needless re-orientation, not against boundaries: a turn ends when the lead is waiting on subagents, never stretched to pack more in. Quality cost: none.

**D29 — The reference half of every pair is prepared once.** Alternative: the lead prepares both sides every round, in prose. `pair --prepare` extracts the matched part, attaches the adapter and the reference's floor outputs once per piece; a round copies ours and assigns labels; the confirming critic gets the same files with the labels inverted, and nothing is rendered again after freezing. Quality cost: a mistake in the matched part lasts the whole piece; it is the lead's judgment, recorded at round zero where the user can see it in the plan.

**D30 — Floors run once; critics get the outputs.** Alternative: every critic reruns everything from scratch. The reference's floor results are computed once per run and ours once per round, and both land in the pair as files; the critic is told to rerun anything it doubts. Quality cost: a critic that trusts a stale output file; the files are regenerated every round and the citation check still requires evidence it opened or ran.

**D31 — The lead's own rerun of a cited command applies to wins only.** Alternative: once a round, as before. A wrong loss costs a round; a wrong win ends the run; the check goes where the mistake is expensive, which is also where the confirming critic already is. Quality cost: a fabricated citation in a loss goes unchecked and costs one round.

**D32 — Pair preparation, the status line, metrics and the gate evidence are commands.** Alternative: the lead reasons through the same steps every verdict. One `pair` or `swap` per verdict; `status`, `metrics` and `gate` are computed from the log. A command also cannot leak a label by habit. Quality cost: none; D24 carries the maintenance cost.

**D33 — Two conditional specialists take work off the lead.** Alternative: the lead writes every floor and freezes every reference in its own context. A floor author writes the required suite, the held-out set, the hostile script and the benchmark from the lead's brief, returns paths and is discarded; a freezer does the same for a large reference, as data only. Both are conditional on size, stated as numbers (a reference beyond 12 files, floors beyond 60 lines; defaults to tune from metrics), because on a small run the invocation is the larger cost. D14 holds: the author never builds and never judges, and the lead specifies, reviews and keeps custody. Quality cost: the lead reviews floors it did not write.

**D34 — Builder briefs and pairs carry the matched part, not the tree.** Alternative: point every builder and every pair at the whole reference. Less is loaded per agent, and no dependencies, build output or indexes ever enter a pair. Quality cost: a builder that would have learned from a neighbouring module does not see it.

**D35 — Conditional wave smoothing.** Alternative: a smoother at every wave boundary, as D10 had it. It now runs only when pieces in the wave share an edge, a file or one reader experience, a recorded fact and never a grade, and post-smoothing rechecks run only for pieces whose diff changed something no floor can see. Quality cost: a seam nobody recorded is found at the gate instead of at the wave.

**D36 — Session effort is `xhigh`; `ultracode` is no longer the instruction; less is read.** Alternative: `/effort ultracode`, which reverses the second half of D15. Ultracode is `xhigh` plus automatic workflow orchestration, and that orchestration competes with the controller's `next`; the lifted subagent cap it also bought is reachable through the harness's concurrency variable. `high` shortchanges builders and first critics, where quality is bought; `max` is documented as diminishing returns. Effort is lower per role only where a check replaces a judgment: `editor-fast` and `author` run at `high` in their definitions. The example run is read on a first run or an empty workbench only. Write mode asks once for a budget alongside the bar pick and declines to write a prompt for work too small to be worth a loop. Quality cost: a small job that would have benefited from one blind comparison does not get a loop unless the user insists.

**D37 — The gauntlet fits the pipeline: a spec in, a pull request out.** Alternative: free text in, and the lead's word that it won out. A gauntlet is a build-and-test loop, so it reads the artifact before it and writes the artifacts after it. Write mode takes a `spec.md` or `intent.md` path as the goal: the prompt names the file, each "never" sentence is copied whole into the bar paragraph as an invariant (up to three; the lead extracts all of them into the workbench), and the spec's acceptance criteria become floors the lead marks DERIVED until the user confirms them. The run's artifacts are committed with the diff by `gauntletctl commit`, after a secret scan and never anything else: the reference manifest, the plan (the round-zero workbench), the final workbench with both bar sentences, every verdict file, the event log, the report. `promote` opens a pull request whose description links the manifest, the plan, the workbench and the two whole-gate verdicts, and its compliance pass checks the diff against the bar sentence and those verdicts. A whole-gate loss that traces to the goal rather than the build is written as an intent draft, never turned into a coherence piece. What is enforced: the committed set and the scan (the controller); `PROMOTED` only after `PR_MERGED`, which `status` reads from the remote and the lead cannot submit; "no run merges its own result" exactly as far as the repository's branch protection goes; the hooks, when checked in. What stays advisory: the skill's text, the compliance pass itself, and the lead's call on whether a gate loss is a scope failure. Cost: a run needs a remote that takes pull requests to promote at all; without one the report says promotion was not applied. Evidence: `dev/gauntlet-loop/tests/test_projection.py`; the spec-input eval case.

**D38 — The run measures itself, and nothing in a run acts on the numbers.** Alternative: the cost estimate in this file, written from reasoning. `gauntletctl metrics` computes everything from the event log and `gauntletctl report` prints it: rounds per confirmed piece; red-floor share of rounds; confirmation flip rate; discarded-verdict rate; accepted `NOT REPRODUCED` rate; parked pieces; escalations per piece by trigger; invocations, lead turns, controller operations, worker-minutes and tokens per confirmed piece (tokens from the transcripts the stop hooks name; lead turns counted by `status`, kept apart from controller operations because machine-side chatter is not model context); spend against each budget, unused reserve, ceiling hit; counts by failure class; and every value metric of the mechanism table below. Why each: red-floor share is what D26 should move; the flip rate is the first critic's reliability and the only evidence that could justify or refute a change to D7; discarded and not-reproduced rates say whether critics are inspecting; parked pieces and escalations say whether bars are set in reach. A human reads them across runs; the strength of a check never varies at run time. Cost: a lead turn is an event in the log. Evidence: `dev/gauntlet-loop/tests/test_projection.py`.

**D39 — The skill is tested, write mode and critic both, and a drop blocks the merge.** Alternative: read the diff and trust it, which is how every earlier change to this skill shipped, including the ones that let a manufactured bar through. `dev/gauntlet-loop/eval/write-mode/cases.json` holds twelve goals as data with their checks: the manufactured-bar run that motivated this release first, a suite alone, two goals with no referent, one too small for a loop, a "never" invariant, a named and an unnamed budget, a code goal, a spec file as input. `dev/gauntlet-loop/eval/run.sh` runs them through the harness non-interactively with `SKILL.md` as the only instructions (`--skill-only` puts `references/` out of reach, which is how the phase that cut `SKILL.md` to a third of its size knew it had lost nothing). `dev/gauntlet-loop/eval/critic/` holds three frozen pairs for each of the seven domains, two where the better side is not in doubt and one near-tie, and `dev/gauntlet-loop/eval/run_critic.sh` runs the shipped `reader` definition on each in both orders. The critic gate is two numbers, so a shape miss can never hide a flip: picks (the known-better side in both orders; on a near-tie a WINNER and no hedge; any flip fails) and shape (the share of replies the controller itself would accept). Both runners pin model ids, so a harness upgrade never reads as a skill regression, and `dev/gauntlet-loop/eval/baseline.json` records the lowest of three consecutive runs: a single stochastic miss on a twelve-case suite would otherwise block every merge or teach everyone to re-run until green. `.github/workflows/gauntlet-eval.yml` runs the free checks (sizes, harness tokens, word count, the controller and hook tests) on every pull request that touches the skill, and both suites in full when the repository has an `ANTHROPIC_API_KEY` secret; without one they are skipped, the gate rests on the free checks, and the suites are run by hand before a skill change merges; its `gate` job is the one to require in branch protection, and it passes when nothing relevant changed. Every run that exposes a gap in the skill becomes a permanent case. Cost: about three dollars of API use per gated pull request at 2026-09 prices, a repository secret, and 21 pairs to keep honest. What the first baseline found: across 126 critic verdicts there was no wrong pick, no hedge and no order drift; about one reply in five opened with its conclusion before the verdict block, which the controller discards, and that is the behaviour D5 exists to stop. Evidence: `dev/gauntlet-loop/eval/baseline.json`.

## Every expensive mechanism: what triggers it, what bounds it, how it ends

Nothing below is removed. Each is fact-triggered, bounded and given an exit, so no mechanism runs without limit and none runs when nothing called for it. `references/running-the-loop.md` states each bound and exit where it describes the mechanism, and `gauntletctl metrics` emits every metric in the last column.

| Mechanism | Trigger (a fact, never a grade) | Bound | Exit | Value (what it removes; the metric that would show it isn't) |
|---|---|---|---|---|
| Fresh critic per round | a builder returned and floors are green | one per piece per round | verdict filed | builder self-approval; discarded-verdict rate |
| Confirming critic | first critic picked ours | one, swapped, other model | both pick ours, or the loss is routed | false wins from position and self-preference; confirmation flip rate |
| Escalation: split | same gap twice | one split per repeat | new pieces enter the table | a piece too coarse to close its gap; rounds per confirmed piece after split |
| Escalation: fresh builder | same gap after split | one | takes the piece | a builder's fixed frame; gap closed within two rounds of the swap |
| Escalation: variants | same gap after fresh builder | two first, third only if both lose; one escalation at a time across the run | best of ours continues the piece | convergence of all builders on one wrong approach; share of variant escalations whose winner then confirms |
| Parking | ladder exhausted, a boundary hit, an irreversible action needed, allocation and reserve spent | — | listed in the report; user decides | unbounded grinding and unsafe action; parked pieces per run |
| Champion-challenger | a piece has no pairable referent | one extra artifact per verdict; champion cached; one more invocation per converging piece | challenger fails twice and two fresh critics on different models name no movable gap | pieces with no loop at all; converged pieces later reopened at the whole gate |
| Wave smoothing | pieces in the wave share an edge, a file, or a reader experience | one smoother; rechecks only for judgment-visible diffs | rechecks pass or reopen | seams found late at the gate; whole-gate losses on coherence |
| Whole gate | every piece confirmed | one smoother, two critics | whole confirmed, or a coherence piece opens | piecewise wins that lose as a whole; whole-gate loss rate |
| Coherence piece | whole gate lost | same ladder as any piece | confirmed, or parked | a gate loss with no owner; rounds to confirm coherence |
| The run | user pasted the prompt | an envelope of invocations and wall-clock: local, escalation reserve, whole-gate reserve | win, all parked, ceiling, or the user | a run with no end, and a gate never reached; share of runs ending on ceiling, unused gate reserve |
| Per-piece allocation | a piece's spend reaches its allocation | one allocation per piece from the local budget | enters the ladder; never lowers the bar | a moving-gap piece eating the run; share of escalations triggered by spend rather than a repeated gap |

The table is architecture, not documentation. A new mechanism enters the skill only with all five columns filled, and a mechanism whose value column stays empty across three measured runs is a candidate for removal in the next version: by a human, from the numbers.

## Reading the numbers

For the human who reviews runs. Nothing in a run acts on any of this, three runs is the minimum before a number changes the skill, and safety floors never change on the strength of a metric.

- A high confirmation flip rate means confirmation is earning its cost. A flip rate near zero across several runs is the one signal that would justify revisiting D7 for the next version.
- A high red-floor share means the builder self-check (D26) is not working.
- A high escalation rate means the split or the bar was wrong at round zero; a high share of escalations from spend rather than from a repeated gap means gaps keep moving, which is a bar or a critic problem before it is a builder problem.
- A high discarded-verdict rate means critics are not inspecting; a high accepted `NOT REPRODUCED` rate means they are inventing.
- Many failures classed `evaluation` means the floors were wrong, not the builders.
- A high share of runs ending on the ceiling, or parked pieces in every run, means bars are being set out of reach. Unused gate reserve in every run means the gate's share is too large.
- An attestation conflict is never noise: read it first.

## Why each rule is there

| Rule | LLM failure it removes |
| --- | --- |
| Fresh context, no builder notes, no history | The critic anchors on the builder's justification and agrees; a reused critic conforms to its own last answer and, having seen which side changed, knows which side is ours |
| The lead fetches; the critic never hears the reference's name | A critic that knows which side is the reference judges the name, not the work |
| Coin-flip labels; confirming critic with the order swapped | Pairwise judges favour a position, and a swap can flip the verdict; one lucky order looks like a win |
| Confirming critic on a different model | A judge favours text that reads like its own model's output, label or no label; against a human-made reference that is a thumb on ours, and two same-model critics agree for the same reason |
| Wins confirmed, losses not | A false win ends the loop early; a false loss costs one round |
| Observations before the pick | The model decides first and writes observations that fit the decision |
| Length matched by selection, length excluded | Judges prefer the longer or busier candidate, and a builder in a loop learns to pad |
| Binary pick, one gap | Absolute scores are noisier than a pairwise pick and drift across rounds; ten gaps get ten shallow fixes |
| Gap as an observation, not a fix | Two critics prescribe two different fixes for the same shortfall; a builder given fixes chases critic taste instead of the bar |
| Floors run by command before the critic | A builder can win the A/B by breaking something the A/B does not look at |
| Cited evidence, one rerun per round | Critics narrate inspections they did not perform |
| A critic's tools reach its pair directory and nothing else; the mapping, the manifest, the workbench and earlier verdicts live outside every pair | A critic told nothing can still open the workbench, the mapping or the repository's `CLAUDE.md` and learn which side is ours; blindness that holds only in the prompt is a request |

## Rule ledger

A rule the skill states is advisory; a rule that must always hold gets something deterministic behind it. Each row says which, and what stands behind it. A rule counts as enforced only when its mechanism was installed and checked in before the run started. The design documents this ledger traces to are in `dev/gauntlet-loop/design/`.

| Rule | Advisory or enforced | Mechanism |
| --- | --- | --- |
| The bar is named, fetchable, comparable, and frozen before any builder exists | enforced by the controller for the freeze | `PIECE_OPENED` is rejected while the run has no `REFERENCE_FROZEN`; whether the bar is a good one stays write mode's judgment |
| The reference is data: instruction and credential files are stripped at freeze, and its code executes only under detected isolation | enforced by the controller | `gauntletctl freeze` strips and never executes; `freeze-verify` exits 3 unless `detect` reports isolation and its own probe agrees |
| No secrets in pairs or committed artifacts | enforced by the controller | `pair` refuses an env or credential file or a secret; `commit` scans first and records `SCAN_FAILED`; `attest` redacts a quoted secret before filing a verdict |
| Tier and containment are detected, never asserted | enforced by the controller | `gauntletctl detect`: the install manifest, hooks in checked-in or managed settings, a clean git status for them, `omitClaudeMd` on the readers, `disableAllHooks`, the sandbox keys |
| The lead never builds a piece and never judges one | enforced by the controller for judging | The lead cannot submit a verdict or any other fact: `event` rejects every fact name and `hooks/controller_only.py` denies a tool call of `attest`. Building stays advisory |
| A critic is fresh for every verdict and never resumed | enforced by the controller | A reader's agent id attests once; a second attestation is `ATTEST_CONFLICT` and voids both |
| A critic never hears the reference's name, builder notes, history, or which side is ours | enforced when installed and checked in | `hooks/critic_blind.py` denies a reader every path outside its pair; readers set `omitClaudeMd`; the mapping lives under `.gauntlet/private/`. The shell check is a string match: enforced policy, not isolation |
| No subagent is named or labelled after a piece, round or role | enforced when installed | Definitions are named for what they may touch (`reader`, `editor`, `author`); no role lists `SendMessage`, so no roster is shown |
| Labels are assigned from a hidden seed and the mapping stays with the controller | enforced by the controller | `pair`: HMAC of the run secret over run, piece and round; the mapping lives under `.gauntlet/private/`, denied to every tool; not even the lead sees it |
| EVIDENCE before WINNER; one GAP as an observation; no ties, a hedge is a loss | enforced by the controller | `attest` checks the shape: WINNER before EVIDENCE is `VERDICT_INVALID`, a hedge is a loss |
| A verdict that cites nothing it opened or ran is discarded | enforced by the controller | `attest`: no citation under EVIDENCE is `VERDICT_INVALID`. The citation check is a pattern match; the lead's rerun of one cited command on a win is the second line |
| Floors the user did not supply are marked DERIVED; a finding a command could have caught becomes a held-out test; the plan is committed before any builder exists | DERIVED and the plan commit are recorded by the controller; converting a finding is advisory | `floor add --derived`, `commit --plan`; after it `hooks/protect_floors.py` denies the floor trees even to an author |
| Command floors run before any critic; a red floor ends the round | enforced by the controller | `CRITIC_DISPATCHED` is rejected unless `FLOOR_PASS` stands for this round, so `pair` refuses |
| A win is confirmed by a second fresh critic, order swapped, on a different model; losses are not confirmed | enforced by the controller | `CONFIRMED` needs a `CONFIRMATION_WIN` attested from `reader-alt` on the inverted pair; `init` refuses to start when the two reader definitions pin the same model |
| A repeated gap escalates (split, fresh builder, variants); it never lowers the bar or ends the loop | the ladder is enforced by the controller; calling a repeat is the lead's judgment | `GAP_SAME_AS_LAST` derives `GAP_REPEATED`; the rung, the variant staging and the park at the end are the controller's. The flip and escalation metrics expose a lead that never calls a repeat |
| No round count and no "no improvement" exit | enforced by the controller | The machine has no such event and the policy no such parameter; the only bounds are the envelope's |
| Every run has a ceiling of invocations and hours that no agent grades, split into local, escalation and whole-gate budgets; a spent allocation escalates | enforced by the controller | Debits ride on the events that open attempts; no piece has a debit path to the gate reserve; `ALLOCATION_SPENT`, `BUDGET_EXHAUSTED` and `RUN_ENDED` are derived, and no work event is accepted after the end |
| The lead writes and holds tests, held-out sets and eval splits; no builder edits them | enforced when installed and checked in | `hooks/protect_floors.py` denies the floor trees to every agent but an `author`; `hooks/builder_boundary.py` denies a builder reads of held-out material |
| A builder stays inside its worktree and away from migrations, infrastructure, deploys, secrets and anything the goal did not name | enforced when installed and checked in | `hooks/builder_boundary.py`; shell checks are string matches |
| A piece has one of seven states and only the listed moves; a stalled piece parks and only a human resumes it | the moves are enforced by the controller; "a human" is advisory (C8) | The table in `references/controller.md`. `resume` needs a named actor and every resume is listed in the report and the pull request, but the lead can run it |
| Every non-win carries a class (`artifact`, `evaluation`, `execution`, `scope`) that decides its route; `BLOCKED` is never a verdict | the class is enforced by the controller; choosing the right one is the lead's judgment | `GAP_ROUTED` and `PARK_REQUESTED` are rejected without a class; verdict-derived losses are always `artifact` |
| A blocked or unsafe piece parks; hooks never ask a human mid-run | enforced when installed and checked in | Hooks deny and say to return `BLOCKED:`; `attest` parks the piece when a builder does |
| Builders return one line; nothing inside an artifact mentions the loop | the trace check is enforced by the controller; the one-line return is advisory | `pair` refuses a tree with a loop trace in a filename or a line (a string match), and never copies `.git`, `.claude/` or a `CLAUDE.md` |
| A builder may study the reference and may not reproduce it | advisory | None: prose in the builder's definition and dispatch. The reference reaches a builder as the matched part only, and its code never runs in a worktree |
| One worktree per piece; merge only after a confirmed win | advisory | A builder is bound to the worktree it first writes in (`hooks/builder_boundary.py`); the merge rule is prose |
| Waves are smoothed and rechecked; the assembled whole is judged and confirmed like a piece | the whole is enforced by the controller; smoothing is advisory | The `whole` is a piece of kind `whole` on the same machine, paid from the gate reserve; `wave` reruns floors on the merge |
| The workbench is a projection of the event log; nobody edits it | enforced by the controller, and by hook when installed | Regenerated after every transaction; `hooks/controller_only.py` denies writes under `.gauntlet/` outside `wt/` and `staging/` |
| Every turn ends with the status line | the line is the controller's; ending the turn on it is advisory | `gauntletctl status` prints it verbatim |
| The lead never writes that the bar is out of reach | advisory | None: prose. The ceiling (D21) is what makes it safe to keep |
| A harder bar is a new run | enforced by the controller | One run per checkout: a second `init` is rejected |
| No run merges its own result | enforced by branch protection, where the repository has it | `PROMOTED` follows only `PR_MERGED`, which `status` reads from the remote; the lead cannot submit it |
| The run never writes or edits its own tooling, state or policy | enforced when installed and checked in | `hooks/controller_only.py`; the policy version is pinned at `init` and a changed one is refused mid-run |
| The paste prompt is one block, 270 words at most, first and last lines fixed | enforced in CI for the template and the examples; advisory for a prompt write mode produces | `dev/gauntlet-loop/eval/wordcount.py` assembles and counts each example; the write-mode cases check length, the first line's two exits and the different-model rule on real output, against a baseline |
| A change to the skill does not lower write mode's or the critic's pass rate | enforced by branch protection, where the repository requires the `gate` job | `.github/workflows/gauntlet-eval.yml`, `dev/gauntlet-loop/eval/baseline.json` |

## Cost

A run is dozens of agents: every round is a builder turn plus a critic, a win adds a confirming critic, an escalation adds three builders, and the whole gate adds a smoother and two more critics. Five pieces over four rounds is on the order of forty to fifty agent invocations before the gate. That is the price of the method; D15 and D25 to D36 are what keep it there, and D21 is what bounds it: that estimate, about ten invocations a piece, is the seed of the default envelope. It is an estimate from reasoning. It will be replaced by measured numbers from `gauntletctl metrics` once three real runs exist, and the envelope's proportions with it.

## Alternatives this skill decided against

Each is argued in the entry named.

| Alternative | Decided in |
| --- | --- |
| A `/loop until the critic picks ours` line inside the prompt, and `ultracode` as the prompt's last word | D11 (the goal command leads the prompt; the harness holds the loop), D15 and D36 (effort is a session setting; the word is not in the prompt) |
| One critic; the piece is done when it picks ours | D7 (a win is confirmed by a second fresh critic, order swapped, on a different model) |
| The critic opens the real reference itself and hears its name | D8, D16 (the lead fetches and freezes; the critic never hears the name and cannot reach anything but its pair) |
| The smallest pieces that can be judged on their own | D25 (coarse first; a repeated gap splits further) |
| No default cap: only the user ends a run that is not winning | D21 (a ceiling that counts and never grades) |
| A supplied reference is used as given | D17 (a supplied bar is tested; a manufactured bar and a suite alone are refused) |
| Telling the critic to be harsh | D4, D5 (procedure, not adjectives: a binary pick, evidence first, no ties) |
| PASS/FAIL per criterion with FAIL as the default, returned with specific fixes | D4 (pairwise for taste, commands for what is objective), D5 (one gap as an observation, never a fix) |
| Several critics with different lenses, votes combined | D6 (one critic per verdict; lenses become floors, reading floors, or pieces) |
| A minimum and a maximum number of rounds | D7, D2 (no round count; confirmation does the work a minimum was for) |
| Stop when two consecutive rounds show no improvement | D2 (that exit is the lead grading its own run; the ladder and parking replace it) |
| The critic keeps the held-out checks | D14 (the lead specifies and keeps custody; critics are fresh every round, so they cannot) |
| A builder in a clean context every round | D9 (the builder keeps its context while the gap changes; a repeat escalates) |
| Smoothing once at the end, optional, the whole not judged | D10, D35 (the assembled whole is judged and confirmed like a piece) |
| A method document the agent follows, with a meta-prompt | D1 (one short prompt; the method is for the lead who runs it) |
